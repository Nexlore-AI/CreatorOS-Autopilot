# Nexlore reel playbooks

What the daily run reads before it writes anything. Modelled on the AdamX video agent
playbooks (`../../video-agent-example1.md`), adapted for 40-second Hinglish reels that go
to Instagram and YouTube from one render.

| File | What it governs |
|---|---|
| `01-story-engine.md` | **Read first.** Story spines, the open-loop rule, audience connection, the register that makes narration sound read-aloud |
| `02-hinglish-voice.md` | Hinglish for every slot: script rules, register, TTS safety, voice pacing |
| `03-platform-metadata.md` | One video, two metadata packages: Instagram caption vs YouTube title/description/tags |
| `04-craft-and-animation.md` | Motion and layout rules, spec limits, technical targets, and the two known gaps |
| `05-critic.md` | Every check that runs before a reel is queued |

## The short version

- Open a loop in scene 1, close it in the payoff, carry **one concrete example** through
  both. A storyline is a tension, not a better ordering of facts.
- Hindi carries the sentence; English carries the subject matter. Devanagari for Hindi,
  Latin for tech terms, numbers spoken as English words.
- Screen in English, voice in Hinglish, captions in Roman Hinglish.
- The voice adds to the screen; it never reads it.
- Write two metadata packages, not one caption posted twice.
- Text animates in, then holds perfectly still. Life comes from the background.
- Every number traces to a source opened today, or the reel does not ship.
